## Verbindlicher Dokumentationsstandard

Jede neue Funktion muss mindestens folgende Bereiche aktualisieren:

1. Benutzer- oder Administratoranleitung
2. Entwicklerhinweise bei Architektur- oder API-Änderungen
3. `CHANGELOG.md`
4. Tests beziehungsweise Testanweisungen
5. Versionsstand, falls ein neuer Entwicklungsstand veröffentlicht wird

Die Dokumentation beschreibt den tatsächlichen GitHub-Stand. Geplante Funktionen müssen ausdrücklich als geplant oder noch ungetestet gekennzeichnet werden.
